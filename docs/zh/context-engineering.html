Context Engineering：上下文不是越多越好

上下文太长会导致模型注意力稀释。就像去医院看病，你不会把出生以来所有病历都带过去，而是只带这次相关的几份检查报告。

30 秒版 · 只记这 3 句 实验台曲线与权重为教学示意
  1. 01 上下文不是一锅粥，按生命周期分四层管理。
  2. 02 证据塞在长上下文正中间，准确率可能低于不给文档。
  3. 03 多轮对话用滚动摘要保底，工具与文档靠 JIT 按需加载。

“context engineering is the delicate art and science of filling the context window with just the right information for the next step.”

来源：@karpathy，2025 年 6 月 25 日
Prompt Engineering
关心“怎么写指令”

设计系统角色、语气约束、Few-shot 示例与输出格式，决定模型以什么方式思考和回答。

Context Engineering
关心“放什么信息、放哪里”

在每一步动态筛选有用片段、控制 Token 预算并排列顺序，避免噪声稀释模型注意力。

多轮对话状态管理：试着把窗口“玩坏”

多轮对话里，“按消息条数截断”有个常见陷阱：只要用户突然粘贴一段几千 token 的报错堆栈，按条数保留就会瞬间撑爆预算；而按 token 预算截断，这一条堆栈又会把前面所有对话全部挤出去。试试调整窗口大小，或者直接：

工程实现参考：按 Token 截断 / 增量滚动摘要 / Compaction Beta 代码

1. 滑动窗口（按 Token 预算从尾部倒推，避免单条长日志撑爆）：

trim-history.ts 
function trimHistory(messages: Message[], maxTokenBudget: number): Message[] {
  const estimateTokens = (text: string) => Math.ceil(text.length / 3.5);
  let total = 0;
  const result: Message[] = [];

  for (let i = messages.length - 1; i >= 0; i--) {
    const tokens = estimateTokens(messages[i].content);
    if (total + tokens > maxTokenBudget) break;
    total += tokens;
    result.unshift(messages[i]);
  }
  return result;
}

2. 增量滚动摘要（旧摘要 + 刚被挤出的头部消息合并压缩）：

rolling-summary.ts 
const maxMessages = RECENT_TURNS_LIMIT * 2;
if (updated.length > maxMessages) {
  const toCompress = updated.slice(0, updated.length - maxMessages);
  const toKeep = updated.slice(updated.length - maxMessages);
  const prompt = state.summary
    ? `当前摘要：\n${state.summary}\n\n新增对话：\n${format(toCompress)}\n\n请合并更新成简洁摘要。`
    : `请将以下对话压缩成简洁摘要。\n\n${format(toCompress)}`;
  const newSummary = await summarize(prompt);
  return { reply, newState: { summary: newSummary, recentMessages: toKeep } };
}

动态加载 vs 一次性塞满

把整个仓库或知识库一次性塞进上下文，叫“Context Stuffing（上下文堆填）”。更好的方式是 Just-In-Time（按需加载）：Agent 执行多步任务时，只在需要的那一步拉取对应文件，工具输出用完后即可清除（参考 Context editing 官方文档）。

知识库问答 · 文档量大
动态检索（RAG）+ Reranker 重排

绝不硬塞全文。先粗排召回候选，再用 Reranker 把最相关的 Top 3~5 片段放到首尾位置。

固定短背景知识
一次性放进 System Prompt

几百到一两千 token 的稳定规范直接放进 System，配合服务端缓存既稳定又省钱。

长多轮对话
增量滚动摘要 + 最近 N 轮原文

最近 N 轮保指代清晰，早期历史增量合并进 System 摘要，守住第一轮定下的约束。

Agent 多步任务
Just-In-Time 按需加载 + 用完即清

每步只拉取当前所需文件或目录片段，消化完的冗长工具输出及时清理或摘要。

单次独立任务
四层直接组装，不做历史管理

无多轮膨胀问题，重点是精简 System Prompt、明确输出 Schema 并做好校验重试。

核心工程口诀
只放下一步真正需要的信息

精简规则层、压缩记忆层、重排并清理知识层，把最强注意力留给首尾和当前任务。
