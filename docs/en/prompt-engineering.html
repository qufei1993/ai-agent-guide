Prompt Engineering: From Asking to Constraining Models

Most developers start out thinking prompt engineering is "how to talk to an AI"—until production hits and a crystal-clear prompt still produces flaky outputs. At its core, a prompt is not a conversation with a model; it is structured context that narrows the next-token probability distribution into your desired boundary.

30-Second Summary · 3 Engineering Takeaways
  1. 01 Know whose job it is: enforce hard formats with Schemas, ground external facts with RAG, and use prompts to steer phrasing and boundaries.
  2. 02 High temperature amplifies low-probability rule-breaking tokens; in long prompts, place critical format constraints at the start and end so they don't fade in the middle.
  3. 03 Use edge-case few-shot examples for sarcasm and tricky classification; always isolate user input inside prompt templates to prevent fence-escape injection.

Why the Same Prompt Returns Different Outputs

Even without changing a single character, running the same prompt 5 times can produce 5 different outputs—and even break your format rules. Make a prediction first, then crank up Temperature in the dice machine below.

import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic();

async function generate(temperature: number) {
  return client.messages.create({
    model: process.env.MODEL!,
    max_tokens: 50,
    temperature,
    system: "Output one product name only, max 10 characters, no punctuation, no explanation, no list.",
    messages: [{ role: "user", content: "Name a pair of headphones: studio-grade sound, only 3 hours of battery." }],
  });
}

// Current lab parameter: temperature = 0.0
const response = await generate(0.0);
const textBlock = response.content.find((b) => b.type === "text");
console.log(textBlock?.type === "text" ? textBlock.text : "");

When predicting the next token, an LLM samples from a vocabulary probability distribution: Temperature sharpens or flattens the curve, Top-K keeps only the top K candidates, and Top-P (nucleus sampling) keeps the smallest prefix whose cumulative probability reaches P. In engineering workflows, start at temperature: 0 for classification, extraction, and structured output, and only raise it to 0.7–1.0 for brainstorming; leave Top-K and Top-P at their defaults in most cases.

Engineering Note · Thinking Mode & Sampling Parameters
When reasoning models such as DeepSeek-V4-Pro run with thinking mode enabled, sampling parameters like temperature and top_p are ignored. To isolate temperature effects, explicitly disable thinking mode (thinking: { type: "disabled" })—see the DeepSeek Thinking Mode docs for exact behavior.

As the U-curve illustrates, Stanford and Meta AI researchers showed in Lost in the Middle Source: Liu et al., 2023 ↗ that LLMs pay the highest attention to the beginning and end of long contexts while diluting information in the middle. In practice, separate your prompt into a System Prompt (role, rules, and output contract) and a User Message (dynamic input), combine System / Role / Contextual Prompting, and anchor critical format rules at the start and end.

import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic();

const prompt = `Classify the user review as: Positive, Neutral, or Negative.

Example:
Review: "Great sound quality and solid value for the price."
Label: Positive

Example:
Review: "Pretty average overall, nothing stands out."
Label: Neutral

Example:
Review: "Waited two weeks and it arrived dead out of the box—what a treat."
Label: Negative

Now classify:
Review: "Great sound on these headphones, but the battery life is terrible."
Label:`;

const response = await client.messages.create({
  model: process.env.MODEL!,
  max_tokens: 20,
  temperature: 0,
  messages: [{ role: "user", content: prompt }],
});
Test Puzzle: "When I was 3, my partner was 3 times my age. Now I'm 20—how old is my partner?"
1. Direct Answer ~12 Tokens
60 years old. (Misled by "3 times", blindly computes 20 × 3)
Lowest latency, but error-prone on multi-step logic traps—and impossible to audit where it went wrong.
2. Prompt-Guided CoT ~78 Tokens
1. When I was 3, partner was 3 × 3 = 9 2. Age gap is 9 - 3 = 6 years 3. At age 20, partner is 20 + 6 = 26 Final answer: 26
Reasoning appears inline in the text body, billed as output tokens, and easy for engineers to inspect.
3. Native Thinking Mode Dual Blocks
[thinking / reasoning_content block] At age 3, partner was 3×3=9; age gap stays constant at 6. 20+6=26.
[text block] 26.
Always extract with content.find(b => b.type === "text")—never hardcode content[0].

With few-shot prompting, quality and edge-case coverage beat quantity: shuffle class order in classification prompts and deliberately include 1–2 sarcastic or borderline examples. For multi-step reasoning, CoT (Wei et al., 2022, Kojima et al., 2022) surfaces intermediate steps in the text body, while native thinking modes (such as DeepSeek's reasoning_content or Claude's thinking blocks—see Claude Extended Thinking docs) return a dedicated reasoning block, so you don't need to mechanically append "think step by step."

function buildReviewPrompt(code: string, language: string, rules: string[]): string {
  return `You are a ${language} code review expert.

Review rules:
${rules.map((r, i) => `${i + 1}. ${r}`).join("\n")}

Review the code below and output only a JSON array of issues:

\`\`\`${language}
${code}
\`\`\``;
}

      Prompt engineering is the discipline of knowing where text-level control ends—and executing sharply within those bounds.
