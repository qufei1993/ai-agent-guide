AI Agent Engineering Architecture Map

When a production Agent loops indefinitely, fabricates a stack trace, or rolls back a service without approval, the hardest part is rarely “is the model smart enough?” It is pinpointing whether the failure lives in Context, RAG, Tool Calling, Harness, or Checkpoint recovery. Tracing one real incident across 6 layers makes every boundary unmistakable.

30-Second TL;DR
01
An Agent is not a “smarter model”—it is a stateful control loop wrapped around a stateless LLM. Context assembly, guardrails, tool execution, and checkpoints all run in your code.
02
Many production outages come from conflating adjacent layers: storing mutable user preferences in RAG, adding MCP without Harness guardrails, or resuming crashed workers from a text summary instead of a checkpoint.
03
You do not need a full RAG stack before shipping a minimal working Agent. Nail LLM constraints and a bounded loop first, then add retrieval, memory, and evals where real bottlenecks appear.

Before You Build an Agent: The 3-Tier Architecture Spectrum

The most common engineering mistake is wrapping a 20-line deterministic script in an autonomous Agent loop. As Anthropic emphasizes in Building Effective Agents ↗, start with the simplest architecture that works, and only introduce an open-ended loop when execution paths cannot be hardcoded upfront. Primary Source · Anthropic Engineering

LEVEL 01 · SINGLE CALL
Single LLM + Structured Output

Fixed input, single-turn output constrained by Prompt rules, JSON Schema validation, and optional retrieval.

Best for: Ticket triage, field extraction, summaries.
Strength: Lowest latency, predictable cost, trivial to eval.
LEVEL 02 · CODE PIPELINE
Deterministic Workflow

Multi-step chaining, routing, or parallelization where every branch is explicitly controlled by application code.

Best for: Invoice OCR → rule checks → ERP posting.
Strength: 100% auditable, predictable execution path.
LEVEL 03 · AUTONOMOUS LOOP
Autonomous Agent Loop

Open-ended tasks where the model dynamically chooses the next tool based on live environmental feedback.

Best for: Unknown 500 incident triage, cross-repo bug fixes.
Cost: Requires Harness guardrails, checkpoints, and tracing.

Anatomy of a 2-Turn Production Agent Run

Suppose an on-call engineer sends one prompt to an internal ops Agent: “Checkout API started returning 500s after today’s v2.14.2 deploy. Find the root cause and prepare a rollback plan.” This is a genuine Level 03 task: the model must inspect live logs first (Turn 1) before proposing a rollback guarded by human approval (Turn 2).

Inspect the payloads across both turns and the LLM’s boundary becomes obvious: it does only one thing—read the current token sequence and decide whether to answer or request a tool call. Fetching logs, enforcing permissions, executing commands, and saving checkpoints are all deterministic application code.

Separate the Information Plane from the Execution Plane

Most architecture confusion disappears once you split every Agent component across two orthogonal planes: one controls what the model sees (Information Plane), and the other controls what the program does and how it recovers (Execution Plane).

Strip Away the Framework: The 35-Line Minimal Agent Loop

    

      Regardless of language or orchestration framework, every production single-Agent runtime boils down to the same loop: assemble Context → call LLM → gate with Harness → execute Tool → persist Checkpoint, stopping as soon as the model finishes or hits a hard budget.
    


    

      Reference Code · 6-Layer Minimal Agent Loop Skeleton (TypeScript)
      

        

          

            TypeScript · Minimal 6-layer collaboration skeleton
            
          

          
async function runAgentTask(taskId: string, userGoal: string) {
  // 01 + 02. Context Assembly: load essential rules, grounded RAG docs, and scoped memory
  const evidence = await retrieveRunbook(userGoal);
  const memory = await loadOnCallPreferences(taskId);
  const messages: Message[] = buildContext({ userGoal, evidence, memory });

  for (let step = 1; step <= MAX_STEPS; step++) {
    // 03. LLM Reasoning: stateless call returning text or structured tool calls
    const reply = await callModel({ messages, tools: declaredTools });
    messages.push(reply.assistantMessage);

    if (reply.stopReason === "end_turn") {
      await saveCheckpoint(taskId, { step, status: "done", messages });
      return reply.finalText;
    }

    for (const call of reply.toolCalls) {
      // 04. Harness Guardrails: validate schema, permission tier, and human approval
      const decision = await harness.check(call, { step, budgetRemaining: MAX_STEPS - step });
      if (!decision.allowed) {
        messages.push(toolError(call.id, decision.reason));
        continue;
      }

      // 05. Tool / MCP Execution with idempotency key; truncate output to fit budget
      const output = await executeTool(call.name, call.args, { idempotencyKey: `${taskId}:${step}:${call.id}` });
      messages.push(toolResult(call.id, truncateForBudget(output)));
    }

    // 06. Durable Checkpoint (execution plane) + optional Compaction (information plane)
    await saveCheckpoint(taskId, { step, status: "running", messages });
    if (estimateTokens(messages) > COMPACT_THRESHOLD) compactOldTurns(messages);
  }
  throw new Error("Exceeded MAX_STEPS budget");
}

            Agent Runtime

            Guardrails
