Context Engineering: Why More Context Hurts

Stuffing everything into the prompt dilutes model attention. Just like visiting a doctor: you do not dump every medical record since birth onto the desk — you hand over only the relevant lab reports for this visit.

“Context engineering is the delicate art and science of filling the context window with just the right information for the next step.”

Source: @karpathy, June 25, 2025
Prompt Engineering
Focuses on “How to phrase instructions”

Designing system roles, tone constraints, few-shot examples, and output schemas to shape how the model reasons and responds.

Context Engineering
Focuses on “What information goes where”

Dynamically selecting useful chunks at every step, budgeting tokens, and ordering pieces so noise never dilutes attention.

30-Second TL;DR · 3 Core Context Rules
  1. 01 More context hurts accuracy: burying evidence in the middle of 20 docs drops accuracy below closed-book baselines.
  2. 02 Fixed turn-count windows break under log spikes; combine a rolling summary with recent turns to lock Turn 1 constraints.
  3. 03 Prefer Just-In-Time loading over Context Stuffing so agents keep high signal density and clear stale tool outputs.

Three Ordering Principles for Context Assembly

Putting theory into production comes down to three ordering rules: keep stable System Rules at the very top (so prompt caching hits cleanly), place the highest-relevance evidence at the edges instead of burying it in noise, and pin the current task at the end. multi-turn-context.ts — Sliding window vs. rolling summary 
// 1. Sliding window: keep only the latest maxTurns exchanges
function trimBySlidingWindow(messages: Message[], maxTurns: number): Message[] {
  const maxMessages = maxTurns * 2;
  return messages.length <= maxMessages ? messages : messages.slice(-maxMessages);
}

// 2. Rolling summary: compress older turns once history exceeds threshold
async function compressIfNeeded(state: ConversationState, threshold = 6): Promise<void> {
  if (state.recentMessages.length <= threshold) return;
  const toCompress = state.recentMessages.slice(0, -4);
  state.recentMessages = state.recentMessages.slice(-4);
  state.summary = await summarizeWithLLM(state.summary, toCompress);
}

Just-In-Time Loading vs. Context Stuffing

Dumping an entire repository or knowledge base into the prompt upfront is called Context Stuffing. The scalable alternative is Just-In-Time (JIT) loading: an Agent fetches only the file it needs at each step and clears stale tool outputs once consumed (see Anthropic’s Context Editing docs).

Quick Decision Matrix: Which Strategy Fits Your App

Every common architecture pattern is laid out below for quick comparison. Click any workload tag to highlight matching strategies:

Large Knowledge Base
Dynamic RAG + Reranker

Never stuff large corpora. Retrieve candidates first, then use a Reranker to place the top 3–5 chunks at the edges.

Static Background (< 2K tokens)
Pin in System + Prompt Cache

Keep stable docs in the System Prompt prefix to maximize KV-cache hit rates without RAG overhead.

Long Multi-Turn Chat
Rolling Summary + Recent 4–6 Turns

Compress older turns into structured memory while keeping recent exchanges verbatim so early constraints survive.

Multi-Step Agent Workflows
Just-In-Time + Output Clearing

Fetch files only when needed and clear stale tool outputs to protect reasoning quality across 10+ steps.

One-Shot Tasks
Strict Token Budgeting

Skip history management entirely; assign fixed budgets to Rules, Input, and Output.

Golden Rule
Curate Signal, Never Stuff

Context Engineering is not about filling the largest advertised window — it is about giving the next step only what it needs.
