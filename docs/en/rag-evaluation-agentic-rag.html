1. Retrieval Evaluation: “Not Found” vs. “Ranked Too Low”

RAG evaluation splits into two layers: retrieval quality checks whether evidence reached Top-K, and answer quality checks whether the model used that evidence properly. Blending both into a single score hides which layer broke.

Start with two deterministic metrics: Recall@K and MRR (Mean Reciprocal Rank). Recall@K measures the fraction of ground-truth documents that land inside the Top-K window passed to the LLM. MRR averages the reciprocal rank of the first relevant hit: rank 1 scores 1.0, rank 2 scores 0.5, and rank 4 scores 0.25.

Reading them together prevents wasted work. Low Recall@3 paired with healthy Recall@5 and MRR means the retriever found the evidence, but the reranker buried it at positions 4 or 5. Only when both Recall@5 and MRR collapse should you blame the embedding model or chunking strategy.

2. Generation Evaluation: Pinpointing Breakpoints with RAGAS

Passing retrieval checks does not guarantee trustworthy answers. RAGAS (docs.ragas.io) decomposes end-to-end quality into four metrics, each watching one specific link in the pipeline.

Keep three ground rules in mind: 1) Build eval sets from real user logs—synthetic questions generated from your docs mirror doc phrasing and inflate Recall artificially. 2) 0.8 is a community starting point, not an official RAGAS law; more importantly, no single metric should drop below 0.6. 3) When Precision and Recall trade off, prioritize Context Recall: missing a required step is far riskier than including two extra paragraphs of context.

async function evaluateSample(sample: EvalSample): Promise<RagasScore> {
  const [faithfulness, answerRelevancy, contextPrecision, contextRecall] =
    await Promise.all([
      scoreFaithfulness(sample.contexts, sample.answer),
      scoreAnswerRelevancy(sample.question, sample.answer),
      scoreContextPrecision(sample.question, sample.contexts),
      scoreContextRecall(sample.contexts, sample.groundTruth),
    ]);

  const overall = (faithfulness + answerRelevancy + contextPrecision + contextRecall) / 4;
  return { faithfulness, answerRelevancy, contextPrecision, contextRecall, overall };
}

3. The Fixed-Pipeline Ceiling & the Real Cost of Agentic RAG

After a few tuning cycles, you will hit a class of queries where single-shot retrieval stalls: cross-document multi-hop reasoning. If Document A says “see the SOC2 Audit Retention Policy,” a single-pass retriever cannot know it needs to search for “SOC2 7-year archive” until after it reads Document A.

Agentic RAG turns the retriever into a callable tool. Instead of hardcoding one retrieval pass, the model inspects what it retrieved, decides whether evidence is complete, and issues follow-up sub-queries until it can answer or hits a hard step cap (MAX_STEPS).

That flexibility is never free. Every extra tool round adds another full-context LLM call, another latency hop, and another failure surface. Make a prediction below, then inspect the side-by-side ledger in Lab 03.

for (let step = 1; step <= MAX_STEPS; step++) {
  const res = await client.chat.completions.create({
    model: MODEL,
    temperature: 0,
    messages,
    tools,
  });

  const msg = res.choices[0]?.message;
  if (!msg) break;
  messages.push(msg);

  // Evidence is sufficient when the model stops issuing tool calls
  if (!msg.tool_calls || msg.tool_calls.length === 0) {
    return msg.content;
  }

  for (const call of msg.tool_calls) {
    const { query } = JSON.parse(call.function.arguments);
    const docs = searchKnowledgeBase(query, 2);
    messages.push({
      role: "tool",
      tool_call_id: call.id,
      content: JSON.stringify(docs),
    });
  }
}

4. Pragmatic Rollout Order & Architecture Selection

Do not build a full eval platform and multi-step Agent on day one. The highest-leverage rollout is: 20 real queries with Recall@5 baseline first, RAGAS on production bad cases second, and selective routing to Agentic RAG only for multi-hop traffic.

Avoid overfitting your tuning set. If you have 100 labeled queries, hold out 20 as a frozen validation set and only run it before shipping, so your improvements actually generalize to unseen phrasing.

Filter by Workload

Fixed RAG (Hybrid + Reranker) Default Start

Best for: FAQs, API docs, and single-doc policy lookups with strict P95 < 2s latency budgets.

Key focus: Push Recall@5 above 80% and MRR above 0.6. Around 90% of enterprise KB queries never need a dynamic loop.

Router + Conditional Escalation Production Pick

Best for: Mixed traffic where 80% of questions are straightforward and 20% span multiple linked policies.

Key focus: Gate entry with a lightweight classifier or first-pass confidence score so simple queries stay fast while hard ones escalate.

Full Agentic RAG Use Selectively

Best for: Root-cause incident triage, cross-clause compliance audits, and deep codebase investigations.

Key focus: Enforce MAX_STEPS, token caps, query deduplication, and explicit abstention fallbacks so loops cannot run away.

Minimal Offline Eval Gate Required Guard

Best for: Every change to chunk size, embedding model, prompt wording, or agentic routing rules.

Key focus: Start with 20–50 real queries for Recall@K & MRR; add RAGAS when users report hallucinations or off-topic replies, keeping every metric ≥ 0.6.
